どちらも1つのリポジトリ giftia の中にあります（モノレポ）。画面を変えるなら giftia-frontend/、検索の中身（SQL）を変えるなら backend/ のフォルダ。両方にまたがる変更も1つの PR で出せます。

改善の流れ（できる日に1回）

  1. やりたいことを Issue（やることカード）にして、改善ボードに貼る。担当を決める
  2. git pull で最新にしてから、新しいブランチで変える
  3. 自分の PC で動かして、変更前／変更後のスクショを撮る
  4. PR を出す → 班のだれか1人以上が見て OK → main に取りこむ
  5. このページの「改善ログ」に1行足す

班のメンバーなら、だれでも改善できます（班長だけではありません）。

ルールの要点

  • main に直接 push しない。変更はブランチ＋PR で
  • 作業の前に git pull。「今日はだれが何を」を Slack で軽く決める
  • 1つの PR には1つの変更だけ
  • パスワードなどの秘密（.env の中身）は、GitHub・Slack・生成 AI に貼らない

くわしくは giftia の README（2章）。

⚠ このページは公開ページです。秘密の情報・教材の内容・本名・データが写ったスクショは載せません。
